# Rittenhouse Residence agent coordinate

Before auditing, editing, or describing this website, read
[`docs/SITE-TRUTH.md`](docs/SITE-TRUTH.md). It defines which source owns each
kind of fact and which observations expire.

## Current-source rules

1. `src/lib/facts.ts` and `src/lib/pricing.ts` own approved aggregate property,
   review-snapshot, public-location, booking-link, and pricing copy used by the
   application.
2. `src/data/rooms.json` owns room-level bed inventory;
   `src/data/property-images.json` owns the public tour order and labels.
3. `docs/VOICE-AND-CONVERSION-PLAN.md` owns public voice, address treatment,
   schema restraint, and booking-language policy.
4. `docs/RENTALAGENT-INTEGRATION.md` documents the current website integration.
   Hospitable through RentalAgent owns reservation/calendar operations; it does
   not override approved public property copy.
5. `public/llms.txt` is generated by `scripts/generate-llms.ts`. Never hand-edit
   it or treat an older copy as independent evidence.
6. A deployed-state claim needs a current GitHub/Vercel receipt and a live
   check. A provider/account claim needs a timestamped observation from that
   provider. Source code proves event implementation, not GA4 receipt, email
   delivery, a booking, or a purchase.

## Sources that are not current authority

- `website/**` is the retired Quarto site.
- Root research inventories and build plans describe historical inputs or old
  proposals unless `docs/SITE-TRUTH.md` explicitly promotes them.
- Old handoffs, conversation attachments, PR/issue descriptions, screenshots,
  and campaign drafts are evidence snapshots, not current truth.

When sources disagree, do not average them or choose the newest prose file.
Follow the authority map, verify the live surface when relevant, and update the
owning source plus its generated consumers.

## Privacy and operating constraints

- Public marketing uses the 1800 block of Pine Street, not the exact address.
  Historical source material may retain an address when it is the subject of
  the record.
- Never publish a real tested stay range together with an `open`, `booked`, or
  equivalent result in code, documentation, fixtures, PRs, issues, or handoffs.
- Public date handling is inquiry-only. The browser must not query a calendar
  or display `open`, `booked`, `unconfirmed`, or an equivalent verdict.
- `/api/availability` is a temporary compatibility acknowledgement only. It
  must return the same response for every request, echo no dates, and touch no
  RentalAgent credential or calendar.
- Do not publish credentials, guest data, reservation identifiers, security
  topology, access codes, or private operational evidence.
- Advertising activation, spend, provider mutations, payout, tax, licensing,
  and insurance attestations remain owner-authority actions.

## Verification

For application changes, run the relevant focused tests, `npm run lint`, and
`npm run build`. For public-site truth, also run:

```bash
SITE=https://rittenhouseresidence.com bash scripts/verify-seo.sh
```

The live verifier is broad regression evidence. It does not turn external
account observations into facts.
